Closing the lid is yours again.

### Changed

- **Lid-closed survival is now granted, never taken.** Your own claims (menu, hotkey, bare `awake`) still carry it. A named claim — any program: a cron job, a build, a coding agent — keeps the Mac awake lid-open only, and may *ask* with `--lid`. The cup grows a "?", the menu leads with the ask, and one click answers it: the grant lasts exactly as long as the work it was granted for, then closing the lid sleeps the Mac again. `awake allow` and `awake deny` are the same answer from the shell; deny after a grant revokes it. Until now every programmatic claim silently armed lid-closed survival — six agents working meant a Mac that would run hot in a bag, and nothing on screen said so.
- **The cup now tells you what closing the lid will do.** Outline: sleeping normally. Filled orange: held awake, and closing the lid sleeps it — bag-safe no matter how many claims run. A "?" rising off the cup: something is asking for more, your call. Burning: lid armed, it will keep running with the lid shut.
- **Right-click (and ⌃⌥⌘A) now toggles your claim, and only yours.** Ending yours disarms the lid and leaves every named claim working; starting yours arms it. It used to suspend everything — six working agents went inert because you ended your own session. "Let it sleep" in the menu (`awake suspend`) is still that machine-level switch, as the explicit act it always really was. Each roster row now opens into its own controls: allow, dismiss or revoke a lid ask, end one stuck session or all of an owner's.
- **"Keep display on" now means what it says.** With the box checked, the screen is held on while *anything* keeps the Mac awake — whoever owns the claim. Since 0.2.0 the setting only applied to claims you started from the menu, so a Mac held awake by an agent went dark and locked with the box checked; that was a regression from 0.1.3, and it's gone. A closed lid has no screen to burn, so this setting cannot cook a bag; the lid grant above is what guards that.

### Notes for scripts

- `awake -w PID` and `--label` claims no longer arm the lid flag. If a job must survive the lid closing, add `--lid` and the human grants it. Everything else is unchanged: same commands, same JSON (`status --json` gains `lidArmed`, `askPending`, and per-claim `wantsLid`/`lidGranted`).
