# awake

One state machine for keeping the Mac awake, lid closed included. Menu bar and CLI are two mouths on the same brain. Replaces Amphetamine and the old `awake`/`asleep` fish functions.

## The mechanism (ground truth)

- `sudo pmset -a disablesleep 1` sets the kernel flag `SleepDisabled` (IORegistry). It is UNDOCUMENTED in pmset(1) but real, and it is the ONLY thing that survives closing the lid on battery with no external display.
- The flag is runtime-only: it resets to 0 on reboot. That is a safety feature we lean on, never re-arm across reboots without live intent.
- IOPMAssertions (`PreventUserIdleSystemSleep`, `PreventUserIdleDisplaySleep`) handle lid-OPEN keep-awake and die with the process holding them. `caffeinate` and every assertion-based app (KeepingYouAwake, Lungo) cannot survive lid close, by design.
- Native clamshell mode needs AC + external display + input device, which is exactly the complaint that started this.
- Read state without root: `pmset -g | grep SleepDisabled`. Absent line = off.

## Architecture

- **Four targets, one direction of knowledge.** `AwakeKit` is the engine (StateMachine, claims, stores, wire) and reads the outside only through `World` (`World.swift`: clock, power, thermal, process table, the pmset flag, assertions, state files; `HostWorld` is this Mac). `AwakeSurface` is every word and picture a human sees, as pure functions of state: the menu model (`Menu.rows` → `[MenuRow]` + `MenuAction`), the glyph (`Glyph`, its AppKit art in `Art.swift`), banners (`Notice`), the CLI (`CLI.parse` argv → `Verb`, `CLI.output` reply → styled lines), and the machine's gestures (`serve` for the wire, `perform` for a menu click, `toggle`, returning an `Effect` for what only the host can do). `awake` is the IO around it: NSMenu drawn from `MenuRow`s, the socket, ANSI, the notifier, the agent. `awake-scene` plays the same engine and surface against a scripted `World` (see Showcase). A word added in the daemon or the client instead of AwakeSurface is a word no scene can show and no other surface can reuse.
- **Effect** lives in the kernel (`pmset -g`, held assertion IDs). **Intent** lives in the daemon as a SET of `Claim`s, mirrored to `~/.local/state/awake/claims.json` so a crashed daemon re-arms honestly. Never conflate them.
- **The suspend switch (`suspendedSince`, `suspended.json`, boot-time validated like claims): the human's "let it sleep".** The menu's "Let it sleep" / `awake suspend` keeps every claim (present and arriving) but `apply()` wants nothing, so the Mac sleeps normally; resume (`toggle` again, `awake resume`) ticks first WHILE still suspended (a claim that died meanwhile stays dead, and the external-writer check must still know we hold the flag off), then lifts, then applies. The toggle used to be `endAll`, which was asymmetric (off destroyed agent intent, on rebuilt only yours) and not sticky (any hook re-arm undid it silently), 2026-08-17. `endAll` remains the explicit act (`asleep`, menu "End all claims"). A human setting the flag by hand while suspended outranks the switch: adopt + lift.
- **The floor's second net (`sweepBelowFloor`)**: ending our claims at the floor only LETS the Mac sleep; lid open, any other idle assertion (coreaudiod on 2026-08-15: 05:06 floor → 08:45 hibernation at 1%) drains it anyway. Below the floor, on battery, no claims of ours, display already dark, still awake → `pmset sleepnow` (console user, no root), notify out of band, log. Runs every tick until AC or sleep, so a wake back onto battery under the floor sleeps again within a minute.
- **Update check = the active-install ping.** `Daemon.checkForUpdate` (from the 60s poll tick, gated by `config.nextUpdateCheck`: +24h on success, +1h on failure, `updates off` disables): one GET of `awake.untitled.garden/appcast.xml` (User-Agent `awake/<version>`, nothing else). The garden's appcast route counts `update-check` + a salted-IP `ping` row (DAU/MAU) and 302s to R2 `releases/awake/appcast.xml`, the hand-written Sparkle-shaped feed `tools/release/dmg.ts` writes on `mise run publish` (unsigned: awake does not run Sparkle, it reads `shortVersionString`). Newer than the bundle → one `screenNotify` per version (`updateAnnounced`), pointing at brew; `awake status` renders the same nudge from `Status.latestVersion`. The bare dev binary (no bundle id) never checks. Declared in the README as exactly what it is.
- **Lid-closed survival is the human's to grant.** `Claim.modes` is granted effect; `wantsLid`/`lidGranted` carry the ask and the answer. The state machine (`normalized`, applied at engage AND startup re-arm) demotes `.lid` on any named claim — any programmatic caller: cron, build, script, agent — to `wantsLid`; only "you" claims and the machine's own "external" adoption carry `.lid` directly. `apply()` unions `effectiveModes` (modes + lid when granted). A grant is answered from the menu (the ask leads it) or `awake allow`, dies with its claim, and survives a same-key refresh (the answer was given to the work, not one engage call). `awake deny` clears the ask; after a grant it revokes. `lidArmed`/`askPending` are computed truths on the machine, mirrored into `Status`.
- **Claims coexist; nothing clobbers.** Every party that wants the Mac awake holds its own claim (owner label + modes + term); the effect is the UNION of all claims' modes — the same OR the kernel applies to IOPM assertions — and sleep restores when the LAST claim ends, which is what makes the "Sleep restored" notification a true sentence every time. Engaging with the same key (same owner label, or same watched pid) REPLACES that one claim atomically; engaging under a claim that already covers you (superset modes, term at least as long) replies `coveredBy` for transparency but still adds the claim — a covered claim costs nothing now and carries its owner's want if the covering claim ends first. There is no check-then-act anywhere: arbitration is the daemon's, atomic, per engage.
- Owner labels are the human surface: "you" for menu/hotkey/bare-CLI gestures, the watched process's name for `-w` (via `procName`, kinfo p_comm), `--label` for anything else, "external" for adopted flags. They render everywhere state is read (menu, tooltip, CLI, notifications) — never a bare pid as the only identity.
- Every mutation goes through `StateMachine.apply()`, the single choke point. No other code path touches pmset or assertions.
- The daemon (`awake daemon`, SMAppService agent `garden.untitled.awake`, KeepAlive) owns the state machine, the menu bar item, the socket (`~/.local/state/awake/awake.sock`, 0600, one JSON line per connection). The CLI never mutates state itself; unreachable daemon → no agent registered: register it; registered: `launchctl kickstart -k` → retry → loud failure naming the log.
- Reconciliation rules (StateMachine):
  - startup, persisted claims → re-arm the valid ones, drop the stale; none valid → restore sleep, clear.
  - startup or tick, flag ON with no claims → ADOPT as an indefinite unforced claim, owner "external" (converge with manual `pmset` use, never silently undo a human).
  - tick, any claim wants lid but flag OFF → external writer wins, ALL claims end (`.externalOff`), notification fires.
- Safety nets (tick: 60s poll + IOPS power callbacks + LPM and thermal-state notifications + precise expiry timer armed for the nearest deadline + one tick at launch, after the hooks are wired): battery floor always wins even over `forced` and ends EVERY claim; Low Power Mode ends only unforced claims; **the thermal guard** (`thermalGuard`, `ProcessInfo.thermalState`, public, no root) at `.critical` ends every claim whose effective modes hold the lid, `forced` included, and `engage`/`resolveLidWant` refuse lid (`EngageError.thermalCritical`) until it cools, so nothing re-arms on its own; claims without the lid live on. `.critical` only: `.serious` is ordinary sustained load. It exists because of 2026-09-25 (indefinite lid claim in a backpack, `.critical` from 20:12 to macOS's Thermal Emergency Sleep at 23:05, die 95 °C, battery 37 %, no other net fired). Resume runs the guard between lifting the switch and applying, or the lid would arm for a poll interval; `-w` matches pid AND kernel start time (`procStartTime`, sysctl), so a recycled PID can never keep a dead process's claim alive. Refuse to arm below the floor, don't arm what the floor immediately tears down.
- Notification policy lives in ONE composer (`Notice.compose`, from reason + ended + remaining): safety nets always speak; an expired/exited claim speaks only when sleep was actually restored or when it was the human's ("Your 2h claim expired. Still awake: claude · while it runs"); an agent claim ending under other claims is log-only. Silence is a decision, not an accident.
- Park vs end: SIGTERM (install bounce, launchd teardown) PARKS — effect restored, intent kept on disk — so `mise run install` never eats running claims; startup reconciliation re-arms them. Explicit quit and every user-facing end CLEAR. Reboots are guarded structurally: the machine's `isValid` rejects any claim predating `kern.boottime` (`World.bootTime`), which is what keeps "the flag resets on reboot" a real safety property.
- Sudo result semantics: the lid flip is judged from sudo's REAL exit status + stderr (`sudo -n`, stdin `/dev/null`, drain pipes to EOF before waiting). NEVER by re-reading `SleepDisabled` afterward, a safety net legitimately flipping sleep back on is observationally identical to a failed toggle, and confusing them causes spurious grant re-prompts (Sleepless shipped that bug; see prior art).

## Privilege

`/etc/sudoers.d/awake` (440 root:wheel), installed by `awake grant` via one `do shell script … with administrator privileges` (native auth sheet), validated with `visudo -c -f` on a temp file BEFORE landing (a broken sudoers file locks sudo machine-wide). Pinned to the installing user, the narrowest rule that works:

```
<installing-user> ALL=(root) NOPASSWD: /usr/bin/pmset -a disablesleep 0, /usr/bin/pmset -a disablesleep 1
```

`awake grant` verifies by flipping the flag to its CURRENT value (proves the grant, changes nothing). The rule content is 440 root and unreadable as the user, so tightening an installed rule needs `awake grant --force` (unconditional reinstall). `awake grant --remove` deletes it. The same shape works for any tool needing one narrow root capability.

## Ops

- Build/install: `mise check` (0-warning gate) · `mise run install` (assembles by hand, no Xcode, into `~/Applications/awake.app.staging`, signs it with the Developer ID (REQUIRED, SMAppService refuses ad-hoc), swaps the whole bundle in with one `mv` the way Homebrew does, CLI symlinks into the bundle, then `awake agent install`, which restarts the agent into the new image) · `mise run uninstall` (unregisters while the bundle still exists: SMAppService resolves the agent through it). The bundle exists for identity (defaults domain shared by CLI and daemon, stable signature); it is NOT enough for real notifications — see below.
- Logs: `~/Library/Logs/awake/service.log` (every transition, before/after state).
- Screaming survives release: world-model violations use `precondition`/`fatalError`, never `assert` — `assert` compiles out under `-c release`, which is what `mise run install` ships. A daemon that cannot bind its socket must die loudly (KeepAlive restarts it, the log says why), not run deaf.
- Menu bar: left-click = menu, right-click = toggle of the HUMAN's claim only: yours running → end it (lid disarms, named claims keep working — consent made this safe, the pre-0.5.0 suspend-all toggle existed because ending everything destroyed agent intent), none → start yours (arms lid), suspended → resume + start yours. "Let it sleep" (suspend-all) and "End all claims" are explicit, unbadged menu items. Roster rows carry submenus: lid verbs per owner (allow / dismiss / revoke), end per claim or per owner. Menu grammar, three registers kept strict: the roster is one line per OWNER (pids demoted to a count, full detail in the tooltip — `Words.summarize`); the checkmark is STATE (your running claim's duration, never a default — a checked default reads as a claim that isn't there); the gesture is the toggle chord's key badge (`MenuRow.toggle`; the daemon draws the LIVE keymap binding, remaps included), worn by the one item the toggle would hit ("Resume" while suspended, "End your session" while you hold a claim, else the duration it would start), so the chord works with the menu open and the badge is never a lie. Glyph: one symbol, two axes — cup ink says whether anything holds the Mac awake (outline = no, filled orange = yes); steam is the LID axis only (none = bag-safe, "?" = a named claim asks, burning red-heavy = lid armed). Overlay states compose onto the filled cup so held states share one set of metrics. `scripts/glyphlab.swift` (`mise glyphlab`) previews candidate glyph states live in the bar: left click cycles variants, right click cycles states.
- Global hotkey: ⌃⌥⌘A = same toggle, via swift-utils Keymap (`ActionSet` + `KeymapStore` + `GlobalHotkeys`, Carbon underneath, permission-free). Remap from the CLI: `awake hotkey ctrl+alt+cmd+a` (`--reset` restores the spec default) — it writes the daemon's own defaults domain (the CLI symlink resolves into the bundle) and bounces the daemon so Carbon re-registers.
- Notifications: the two-process split Apple DTS points at (forums 804854: `UNUserNotificationCenter` is structurally unavailable to a launchd agent, TCC only arbitrates the permission for LS-launched user-context apps; verified 2026-08 with Developer ID + lsregister + LS launch, UNErrorDomain Code=1 every time; and KeepAlive is load-bearing, so the daemon stays a launchd agent). `awake-notifier.app` (its own target, own bundle id `garden.untitled.awake.notifier`, nested at `Contents/Helpers/`, signed inner-then-outer) is LS-launched per message by `Daemon.screenNotify` (`open -g -n -a … --args "<msg>"`), checks `getNotificationSettings`, posts, exits; denials and errors append to service.log because an LS-launched app has no stderr anyone reads. Permission is asked IN CONTEXT per Apple's guide: `awake agent install` runs the helper with `--prime`, which prompts only while `notDetermined` and posts an intro banner saying what will arrive there (never at a 3am floor end behind a closed lid); alert + sound only, no badge, no provisional (a safety-net message must not be history-only). The bare development binary (no bundle, no helper) logs the message and nothing else.
- **Notification permission is a swift-utils Grant, rendered, never just logged.** Only the helper can read its own settings, so EVERY helper run (message, `--prime`, `--probe`) records `NotificationReach` (`notAsked`/`denied`/`silenced`/`allowed`; silenced = allowed but alerts off or style None, which for a safety net is denied) into `~/.local/state/awake/notifications.json` (`NotificationStore`). The daemon probes at launch and on every menu open (off-main LS launch), `Status.notifications` carries it, and every surface renders `Notifications.standing(_:)` of it and nothing rawer: the menu's lead row (`NotifierGrant`, in `Notifier.swift`; askable → "Allow…" runs `--prime`, broken → "Open Settings…" deep-links the HELPER's bundle id, the row belongs to whoever posts), restyled by the 1 Hz open-menu ticker so returning from Settings clears it live; `awake status` prints broken. The sudoers grant renders through the same `Standing` + `style` path (askable, never broken: one click raises the admin sheet). Grant's module exports its own `Claim`, so awake-target files import it SCOPED (`import enum Grant.Standing`); the local sudoers type is `Sudoers`, never `Grant`. - CLI: `awake` · `awake 2h|90m|45` · `awake --until HH:MM` (next occurrence, tomorrow if past) · `awake -w PID` (claim named after the process) · `--label NAME` · `--display` · `asleep`/`awake off` (ends EVERY claim) · `awake off WHO` (owner prefix or pid, ends the matches) · `awake --lid` (a named claim's ask for lid-closed survival) · `awake allow|deny [WHO]` (the human's answer; deny after grant = revoke) · `awake check [WHO]` (the caller's half of the wish-not-lock contract: exit 0 in effect / 2 inert / 3 gone) · `--on-end CMD` (per-claim end hook, any reason, `/bin/sh -c` with the reason as `$1` — fires synchronously in `Daemon.notify` before a closing end lets the Mac sleep, same contract as the global notify hook) · `awake status [--json]` (Status is Codable; the JSON form is the scripting surface, `.claims` is the array) · `awake floor N` · `awake notify [CMD]` · `awake hotkey [COMBO]`. Fish aliases `caf`/`cof`/`coffee`/`amph` point at `awake`. Engage replies carry `replaced` (same-key refresh) and `coveredBy`; end replies carry `ended` — breadcrumbs render from one round trip.
- Config (`~/.local/state/awake/config.json`): floor, last duration, display preference. Decode is per-key tolerant — adding a field never resets the rest. `lastMinutes` is HUMAN muscle memory: only menu/hotkey gestures teach it, never a wire client (a script's `awake 5` rewriting the right-click default is the bug this rule kills). The display preference is GLOBAL, applied at the choke point: while any claim holds the machine awake, the display is held too (it cannot burn a bag — a closed lid has no lit panel; lid is the dangerous axis and consent-gated). `--display` is the per-claim opt-in when the preference is off.
- Menu: the open menu redraws at 1 Hz (NSMenu freezes titles otherwise; the ticker rides `.common` runloop mode because menu tracking runs the event-tracking loop): the rows are rebuilt from the status the menu opened with plus the current time and grant standings, and applied in place while the shape holds (`Daemon.refresh`); a changed shape waits for the next open. It never ticks the machine, which could end a claim under the pointer.

## Showcase (scenes)

awake is shown on the web by itself, not by a recording. `scenes/<feature-id>.scene` is a story in the world's terms (clock, battery, lid, processes) and the human's (`$ awake …`, open the menu, click a row, the chord); `awake-scene` plays it through the real `StateMachine` and `AwakeSurface` against a scripted `World` and writes `scenes/<feature-id>.json`, the timeline `@ag/macos` plays (github.com/adriangalilea/ui: the menu bar, the menu, the terminal, banners, the lid folding on a MacBook). The script's grammar is the doc comment on `Player` (`Sources/awake-scene/Player.swift`).

- **`hero.scene` is the value in one breath** (turn it on, close the lid, still working): the garden's hero and the README film, whichever feature leads. It stays that short; everything else belongs to a feature card's scene. Captions are one short line, after the thing they tell. A caption says what happened in terms that hold for any viewer ("Your agent has hours of work ahead.", "It kept working the whole time."), never the example on screen (which files, how many tests: the screen already shows that, and nobody relates to it). Where the viewer can act, it instructs with the real gesture ("Press ⌃⌥⌘A to keep your Mac awake."), never a slogan ("one chord keeps the Mac awake" is nothing a viewer can repeat). The agent's activity is what makes a story believable: the prompt typed, a reply, tool calls before the lid, real work (a failure and its fix) behind it. The last caption is what someone arriving late reads, so it carries the whole story on its own ("The lid was shut for 1h 50m, and your agent finished the job."). Its `poster` line marks the one frame a still shows: the garden's link card is that frame of the live stage (`pnpm artwork` in the garden captures it; recapture and commit when the scene changes).
- **Something is always running**: a story can open a coding agent in the terminal (`agent claude|codex`, drawn by ui's `claude-code` / `codex`). The agent's own words are the story's; what it runs through awake (`agent run awake -w … --lid`) goes through the real CLI and engine, so its tool result is awake's actual answer. That is the real integration: an agent following awake's skill asks for itself, and the human grants the lid.
- **The switch is one switch**: the mouse (right-click the cup), the chord and the CLI flip the same claim, and `menu-bar.scene` shows all three. A click in a scene is made by a visible pointer that travels there, with the pressed button shown.

- **Nothing is typed twice.** Every menu row, CLI line, banner and glyph in a scene is what this code produces for that state; `art.json` is the glyph and icon drawn by `Art.swift` itself. A step the app cannot do (a row that is not in the menu, a command that fails without `$!`, a click that would raise the admin sheet) stops the compile with the script's line, and `mise check` compiles every scene, so a menu change that breaks a story fails the gate and a stale timeline shows as a CI diff.
- **The app decides content, the web decides pacing.** Steps carry only the pauses the author wrote (`@ms`); typing speed and default beats live in `macos-session.ts`.
- **Verbs**: `mise scene` (compile into `scenes/`, the ui studio `public/macos/awake/` and the garden `components/scenes/awake/` when those checkouts exist; stale timelines in those dirs are removed) · `mise scene:watch` (recompile on save; the ui page `localhost:3100/macos` has a scrubber) · `mise film` (each scene filmed on a MacBook by ui's `scripts/macos-film.ts` into `dist/films/` as animated WebP + mp4, then published by the garden's `tools/release/film.ts` to `cdn.untitled.garden/media/awake/films/<id>.webp|mp4`; needs the ui checkout and the garden's R2 env, no server; `FILM=<id>` films one). Filming is faster than the story: the stage is a pure function of scene time, so several pages draw frames in parallel and only frames whose markup changed are photographed; the encoders get distinct frames with their durations.
- **Films are hosted, never committed.** A README shows a film as an `<img>` of the WebP (GitHub plays animated WebP inline; a fifth of a GIF's bytes, full colour). The names are stable and cache for five minutes, so re-filming never changes a link.
- The garden plays a scene in the feature slot whose id matches (`AWAKE_SCENES` in `apps/garden/components/project-demos.tsx`).
- GOTCHA: fish functions shadow PATH binaries. `~/.config/fish/functions/awake.fish`/`asleep.fish` must not exist (removed when this replaced them).
- Quit from the menu runs `launchctl bootout` (plain exit would just get resurrected by KeepAlive).

## Prior art (read before redesigning anything)

- **Sleepless** (`Aboudjem/Sleepless`, MIT, single-file AppKit, read in full 2026-07): source of the sudo-exit-status lesson above, the glyph-by-silhouette convention, LPM auto-off vs deliberate-user-intent (`forced`) split, battery floor, and "reboot resets the flag is a feature". Menu-bar only, no CLI.
- **Newt** (`acheris-labs/newt`, read in full 2026-07): SMAppService root XPC helper whose connection-drop handler restores sleep, code-signature-pinned. The structurally safest crash story, deliberately NOT copied: it demands stable signing and a second binary; launchd KeepAlive + startup reconciliation + persisted intent achieves the same honesty with none of that. Also source of refuse-to-arm-below-floor and live per-mode assertion add/drop.
- **nosleep** (`tmad4000/nosleep`, bash): the CLI UX bar (`nosleep on/off/3600`, scoped passwordless sudo, timed auto-revert). Rejected as a dependency (bash, 1-star supply chain), matched feature-wise.
- **solofan** (unpublished): the privilege pattern, one native auth prompt installs a scoped sudoers drop-in, passwordless forever.
- **strata** (unpublished sibling): the repo shape, SwiftPM engine-as-library + thin executables, mise verbs with a build mutex, argv[0] dispatch, launchd bounce on install.
- **Amphetamine** (closed source, replaced 2026-07): needed its separate open-source Enhancer for closed-lid at all; the right-click toggle gesture survives here.
- None of the open-source menu-bar tools ship a CLI, and the shell CLIs ship no resident guard. The whole reason this exists: safety nets need a resident process, and a one-shot command can't guard anything after it exits.

## Agent integration

- **Claude skill** (`skill/SKILL.md`, symlinked to `~/.claude/skills/awake` by `mise run install`, the `_core` skills convention): agents reach for `awake`, never `caffeinate`/raw `pmset`. Key rules taught: arm `-w` WITHOUT a status check (claims cannot clobber; the old guard was a TOCTOU race), label timed claims, never bare `asleep` programmatically (it ends the human's claim too — `awake off <label|pid>` ends only yours).
- **Agent harness integration**: a session-start hook that arms `awake -w <agent pid>` keeps the Mac from idle-sleeping under long unattended work. It does NOT survive the lid closing by itself: lid survival is the ask (`--lid`) + the human's grant. Each agent's arm is its own claim: several concurrent agents each carry their own, sleep returns when the last live one exits, and the human's session is untouchable by construction. The vigil hooks (`vigil-claude-hook.sh`, `vigil-codex-hook.sh`) arm unconditionally; only the hook's own failure must never kill the session it runs in (subshell + `|| true`).
- Claude Code's own `caffeinate -i -t 300` rolling assertions (the harness spawns them while sessions work) are harmless and redundant next to the lid flag; they die at lid close, which is exactly the gap the hook closes.

## Release

MIT, standalone repo, `swift-utils` consumed as a versioned URL dependency (`from: "0.1.2"`), so a fresh clone builds anywhere.

- **Releasing is LOCAL, by design**: `mise run release` needs the Developer ID in this keychain and the notary key in `~/.appstoreconnect/private_keys`, and neither belongs in CI. CI runs `mise check` and nothing else, so the repo holds no secrets and needs none. Flipping to CI-side notarization later means uploading a p12 + ASC key to GitHub secrets; the shape it would take is specced in swift-utils' TODO (`mac-app-release.yml`).
- `VERSION` in `mise.toml` (`[env]`) is the single source of truth: it stamps `Info.plist` and names the tag. An app has a native version field, so the manifest leads and the tag follows. (A Swift LIBRARY is the inverse: SwiftPM has no manifest version, so the tag IS the version. swift-utils works that way.)
- `notes/<version>.md` is the words gate: hand-written, committed, and the GitHub Release body. `mise notes` drafts it from the commits with git-cliff; the draft is raw material, never prose users read. `mise run release` refuses without it, refuses on a dirty tree, refuses on an existing tag, refuses without a certificate or notary IDs.
- Notarization is judged by `stapler`, not by `notarytool`'s exit status: stapling can only succeed if a ticket was actually issued.
- The signing identity is discovered via `security find-identity` (in the `install`/`release` tasks), never hardcoded, so a fork signs with its own certificate and `mise run install` still falls back to ad-hoc on a machine with none.
- Distribution is `brew install --cask adriangalilea/tap/awake`, plus the dmg on the GitHub Release for anyone who wants it directly. The recipe lives in `adriangalilea/homebrew-tap` (a separate repo because Homebrew only discovers taps by that name prefix; shared with the other apps as they arrive), working copy checked out alongside this one. `mise run cask` rewrites its version + sha256 and pushes; `mise run release` calls it last, since the sha can only exist once the dmg is public.
- **The app owns its agent's whole lifecycle; the cask has no hooks.** The agent is an SMAppService agent (`Agent.swift`): its plist ships IN the bundle (`launchd/garden.untitled.awake.plist` → `Contents/Library/LaunchAgents/`, `BundleProgram`, no per-user paths, so the daemon points its own stdout/stderr at service.log when its parent is launchd). Three moments, each measured on macOS 26 with a throwaway Developer ID agent before building:
  - **Register on first use**: `agent install` from an argument-less LaunchServices launch (`main.swift`: no args, parent pid 1, a bundle; a double click or Spotlight after Quit IS the recovery), from `mise run install`, or from the first CLI call that finds no daemon (`Client.send`), which is how a `brew install` comes alive (the caveats say so). `register()` from a CLI invocation works, Developer ID, no notarization, status `enabled` at once. Right after `unregister()` it fails with EPERM for a few seconds (retried). `enabled` is BTM's record, not launchd's: install only reports success once `launchctl print` shows `state = running`, and re-registers once otherwise.
  - **Upgrade = the daemon restarts itself** (`Daemon.watchImage`, every poll tick): the registration survives a bundle replaced in place, and launchd starts the NEW image on the next spawn, so a different inode at the executable path means park + exit(0) and KeepAlive does the rest. Only into a bundle that satisfies the running code's own designated requirement (`bundleSignedAsSelf`): launchd refuses an unsigned or half-written image as a launch constraint violation (`OS_REASON_CODESIGNING`), and after a few refusals it parks the job in `spawn scheduled` for good, beyond `kickstart`; only a fresh registration revives it. That exact race (restart caught between assemble and codesign) is why `mise run install` stages and swaps.
  - **Uninstall = the daemon removes itself**: deleting the app does NOT unload the agent, and once the process exits launchd retries the missing binary forever (EX_CONFIG). The executable missing two ticks in a row (one absent tick is an upgrade's swap instant) → `endAll(.shutdown)` (sleep restored) → `launchctl bootout` of its own job, which kills the process inside the call, so it goes last. Not `unregister()`: it resolves the plist through the bundle and fails ("Invalid argument") once Homebrew has deleted it. BTM keeps its record; a reinstall reuses it, and `agent install` only kickstarts a job that is running (kickstart on a dead job blocks forever), re-registering anything else. Covers a Trash drag too, which runs no hook anywhere. The sudoers grant stays (removing it needs a second auth prompt: `awake grant --remove`).
- **Why the cask cannot help** (Homebrew 7, `extend/os/mac/sandbox.rb`): cask steps (`postflight_steps` & co., the non-deprecated form) run under `sandbox-exec` with `(deny mach-lookup)` beyond a short list, `(deny lsopen)`, `(deny appleevent-send)`, HOME redirected and unreadable. launchd refuses `bootstrap` to ANY sandboxed caller (EIO, even under an allow-everything profile), `open` is denied, BTM is unreachable. Uninstall steps and `uninstall launchctl:` run on every upgrade too (only `signal:` is skipped), and `launchctl:` also tries sudo. The legacy `postflight`/`uninstall_preflight` blocks still run unsandboxed but are deprecated and print a warning on every brew command. Test cask changes with a local tap copy (`/opt/homebrew/Library/Taps/adriangalilea/homebrew-tap/Casks/`), never by pushing.
- **`~/.local/bin/awake` is a symlink, and through it `Bundle.main` is the symlink's directory, not the app** (measured): SMAppService would look for the plist there, the notifier would be missing, the defaults domain would be wrong. `main.swift` re-execs through the resolved path first thing, so every invocation runs as the bundle's own executable.

## Deliberately not built (decided, not forgotten)

- **Time-sensitive notifications (breaking through Focus).** Feasible, and not worth its permanent cost today. It only helps a lid-open Mac in Focus: behind a closed lid nobody sees a banner and the out-of-band notify hook is what reaches a person, and allowing awake in a Focus mode gets the same result for free. The cost stays forever: a profile only the account holder can mint, one more signing input, and a new failure mode (AMFI kills an entitled helper whose profile is missing). **Trigger to build it**: users who run Focus reporting missed safety-net banners. The design, ready: `com.apple.developer.usernotifications.time-sensitive` is a restricted entitlement a Developer ID app carries only with a Developer ID provisioning profile embedded in the bundle that uses it; Apple's "Supported capabilities (macOS)" table lists Time Sensitive Notifications under Developer ID, so Homebrew and the dmg distribute it like anything else, and such profiles last years. The capability goes on the NOTIFIER's bundle id only (`garden.untitled.awake.notifier`), its profile at `Contents/Helpers/awake-notifier.app/Contents/embedded.provisionprofile` copied in by `assemble.sh`, the helper signed with the entitlement, `interruptionLevel = .timeSensitive` on safety-net ends only (floor, heat, LPM). The daemon never carries it, so a broken profile can only cost banners; the build refuses to sign the entitlement without the profile. No Xcode: the profile is one file, SwiftPM plus hand assembly stays the build.

- **Multi-user concerns** (per-user daemons fighting over the one kernel flag): the sudoers rule is pinned to the installing user, so on a single-user machine the question never arises. A second user could not flip the flag at all. If this ever ships publicly, the adopt/external-writer reconciliation already converges multiple writers, but the grant model would need rethinking (per-user rules mean any of them can disable sleep for all).

## Verification (runnable reality, no test suite)

`mise check` must print 0 warnings. Then: engage → `pmset -g` shows the flag + `pmset -g assertions` shows "awake"; `kill -9` the daemon mid-claims → relaunch re-arms with correct remaining time; engage then `mise run install` → claims parked and re-armed across the bounce; stale claims.json on boot → sleep restored, file cleared; `sudo pmset -a disablesleep 1` by hand → adopted as an "external" claim; `awake -w <pid>` → claim named after the process, ends when pid dies; two claims coexist (`awake` + `awake -w <pid>`) → status lists both, ending one leaves the other's effect intact, sleep restores only when the last ends; engage under an indefinite claim → `already covered` breadcrumb, claim still added; same-key re-engage prints `replaced own claim:`; `awake off <owner|pid>` ends just the match; 1-minute claim → ends within ~1s of deadline with notification naming the owner; ⌃⌥⌘A (synthesizable via System Events `key code 0 using {control down, option down, command down}`) → ends all claims, or starts yours at the checkmarked duration. Floor/LPM/thermal trips remain log-inspection only (not simulatable without draining the battery or cooking the Mac); `awake status` shows `critical heat, lid refused` and the menu a disabled row under the battery while the guard holds.
